# ChatGPT / Codex 跨窗口协作及实时维护规则

## 1. 接入与领取任务

1. 确认 GitHub 仓库、主分支和最新提交 SHA；按根目录 README 的顺序读取当前状态。
2. 说明本窗口的任务、可修改文件、只读证据、完成标准和禁止项。没有原始证据访问权时，必须明确列出缺口。
3. 同一时间让不同窗口负责不同章节/文件；若共同编辑同一处，先生成独立候选，避免静默覆盖。

## 2. 事实和版本

- 新文件或新聊天输出不是自动更高级的证据。原始实验记录、正式 Word 批注和作者新确认分别决定不同问题。
- 发现冲突时先列出来源、位置、拟采用的版本和不确定性；`BLOCK` 关闭前禁止写成确定结论。
- 对论文正文默认给可审阅候选；只有作者明确授权具体稿件及文件，才允许回写本地 Word/实验文件。

## 3. “实时更新”的操作性定义

- 每完成一个**经作者确认**的关键任务，就在**同一会话**更新 `论文总控_接续与进度.md`；发生决策变更则更新 `决策记录.md`，事实问题变化则更新 `待核问题与证据台账.md`。
- 未获确认的候选只能标 `proposed`/`待审`，不得覆盖当前有效定论。
- 不需要将每一句聊天同步到 GitHub；只提交精简且可核查的当前状态、证据和决策。
- 不存在无需任务触发的自动后台同步；下一窗口开始前应重新读取远端最新提交。

## 4. 覆盖与删除（2026-10-28 作者新规则）

- **允许直接覆盖/删除已失效内容**；不再为了保留历史而在文件头部持续添加旧事件日志。
- 操作前核对准确路径、最新 SHA、是否仍有独立文献/数据核查价值以及新旧内容的替代关系。
- 明确过期的版本镜像和冗长进度流水账可从当前树移除；重要来源和仍有效研究笔记保留并在索引说明时间边界。
- 删除/覆盖应在同一个清晰的提交内列出原因；不强制推送、不重写远端已发布历史。误删时通过 Git 历史恢复。
- 对是否失效仍有疑问时，先标注 `待核`，不要仅因文件较旧就删掉可追溯的证据。

## 5. 任务完成交接最小格式

```text
任务 ID/窗口：
读取的 commit SHA：
实际完成内容与交付位置：
本次新增/确认的事实（来源 ID）：
本次决定（作者是否已确认）：
未解决问题 ID：
修改/删除的仓库文件：
提交 SHA 与是否已推送：
下一个窗口的一项明确任务：
```

## 6. 安全边界

- 仓库保持 Private；不未经确认扩展协作者权限。
- 只同步作者授权的精选 Markdown；不推送原始 Word、数据表、录音、完整谈话、内部源图、他人论文或私人文件。
- 上传前逐项核对文件内容与元数据。Git 历史不是清除敏感信息的替代方案。
- GitHub 的文本摘要不是原始论文备份，不能凭摘要宣称对实验或 Word 修订已做全量验收。
