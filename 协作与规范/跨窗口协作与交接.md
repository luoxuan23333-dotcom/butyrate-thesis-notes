# 跨窗口协作与交接｜现行规则

## 一、仓库的角色

本仓库是多个窗口共享**当前有效信息**的入口，不保存聊天流水账和全部草稿。它不自动同步所有会话，也不代替本地 Word、原始 Excel、图表、导师正式批注或文献原文。

## 二、每个窗口的工作闭环

1. **开始**：从 `README.md` 读取最新 `main`、任务、研究事实和导师要求；报告实际接触过的文件，不能假称已读取。
2. **领取**：明确任务 ID、允许访问/修改的文件、输入证据、输出和验收标准。并行窗口避免同时编辑同一文件；必要时分别交候选。
3. **执行**：先核查事实及真正的文献依据，再写候选；冲突标 `【待核】`，不得补造数据、机制、导师原话。
4. **审核**：作者决定采用、修订或拒绝；AI 给出候选不代表作者已确认，更不代表导师已认可。
5. **同步**：经确认的重要变化在**同一任务结束前**更新 GitHub 对应文件及 `README.md` 当前任务表；写清提交 SHA 和未决问题。下一窗口重新读取最新提交。

## 2026-11-05作者最新指令：单文件原位覆盖（明确确认）

**作者要求**：“之后往github更新文件时，旧版本直接替代掉。”此规则适用于之后所有ChatGPT、Gemini、Codex协作产生的Markdown论文译稿、术语表、任务记录和规范。

- **一节论文只保留一个当前工作稿路径**。对同一节的修改用`fetch_file`读取当前SHA，**`update_file`整体替换原文件内容**，不要另建`V2/V3/V4_新稿.md`。版本可记录于文件首部一句，不构造并列文档。
- **旧历史走Git提交记录，不靠重复文件存版本**。GitHub页面的History/提交SHA可回退。禁止为历史保留反复复制同一正文；已有旧版本文件后续在维护对应节时可核查并清理，前提是先修复仍在使用的相对链接，且独立的文献证据分析不能未经核验当作重复稿直接删除。
- **使用稳定文件名**：之后新建章节建议`英文投稿/2.3_英文工作稿.md`等不带V号；当前已经存在的2.2历史命名`2.2_ARTP-UV-ARTP连续诱变_英文初稿V1.md`可暂保持链接兼容，以后**直接覆盖该现有文件**，不因此新建V2文件。2.1现有作者暂定稿也按此规则处理。
- **覆盖前确认**：本轮作者最新决定、权威中文源稿、并行工作是否冲突；只修改作者授权的Markdown，不覆盖中文Word、数据/图、英文锁定图注或已发布PDF。
- **提交后验收**：取远端`main`核实目标路径SHA/最新内容及README/进度链接，记录最终提交SHA。避免仅说“已更新”而不核实。

## 三、覆盖、删除和当前版本

**2026-10-28 作者授权**：仓库当前文件要及时更新；过时、不适用、被新决定取代的文件可覆盖或删除，不必长期保留旧正文或重复台账。

- 删除前准确检查路径、当前提交与替代关系；有独立证据价值的文献分析可保留，但必须说明时间范围及适用边界。
- 不在文件顶端反复追加过期日志，不把历史方案与当前有效方案混在一起。历史版本由 Git 提交记录追溯；不强制推送或改写历史。
- 无法判断是否失效时，先在研究事实文件标 `待核`，不凭日期新旧直接删除可核查证据。
- “实时更新”指任务触发后及时提交，不表示后台自动监控或主动运行。

## 五、一次交接的最低内容

```text
任务/Issue：
读取的 GitHub commit：
使用的原始证据与位置：
实际完成的工作及交付位置：
新增结论（已核实/作者确认/仅建议）：
尚未解决的事实或版本问题：
本次更新、覆盖或删除的仓库文件：
提交 SHA，是否已经推送：
下一窗口应做的具体任务：
```

只纳入可审阅的精简交接，不复制完整聊天历史。

## 六、保密范围

仅提交作者授权的 Markdown；不推送原始 Word、Excel、PPT、未发表原图、完整谈话转写、录音、私人材料、第三方论文 PDF 或凭据。私有仓库不等于自动获得所有资料的上传许可。
